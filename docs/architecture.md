# Архітектура

Конвеєр: **текст → токени → AST → (дерево виводу | семантичний терм) → обчислення / доведення**.
Кожен етап — окремий модуль із чистими функціями, між етапами передаються типізовані структури, а не рядки.

```
 .sipl ──► lexer ──► parser ──► AST (Program, Seq, Assign, If, While, …; кожен вузол має SourceSpan)
                                 │
                 ┌───────────────┼───────────────────────────┐
                 ▼               ▼                           ▼
           analysis        visualization               semantics.build  (правила NS_*)
     (змінні, вхідні)   parse_tree → text/JSON/DOT        │
                         svg → SVG/HTML                    ▼
                                                    term (AS, WH, IF, S^n, id, ⇒, n̄)
                                                      │            │
                                                      ▼            ▼
                                              semantics.evaluate  semantics.proof
                                              (AF_*, state, ⊥)    (poly, formula, B/A/E-кроки)
```

| Модуль | Відповідальність |
|--------|------------------|
| `spans.py` | `SourceText`, `SourceSpan` (зміщення, рядок, стовпець), вирізання фрагмента |
| `errors.py` | `Diagnostic` (код, серйозність, повідомлення, позиція), `SiplSyntaxError`, відображення з кареткою |
| `lexer.py` | токени, ключові слова, `∨/or`, `¬/not`, коментарі `//`, позиції |
| `ast.py` | неізмінні вузли AST; `==` порівнює структуру, ігноруючи позиції; `parts` — впорядковані складники (вузли й токени) для дерева виводу |
| `parser.py` | рекурсивний спуск; пріоритети й асоціативність; помилки з очікуваним символом |
| `unparse.py` | AST → канонічний текст / S-вираз (перевірка round-trip у тестах) |
| `analysis.py` | змінні, присвоювані, вхідні (читаються до присвоювання) |
| `visualization/parse_tree.py` | `PNode` з AST: нетермінали, нумеровані листки, правило виводу, span → text/JSON/DOT |
| `visualization/svg.py` | розкладка за шириною піддерев, SVG з підказками (`<title>`), HTML-обгортка |
| `semantics/term.py` | типи термів, форматування (unicode/ascii/latex), (де)серіалізація JSON |
| `semantics/build.py` | AST → терм за правилами NS_*, з журналом застосованих правил |
| `semantics/state.py` | незмінний стан, оновлення `st ∇ [x ↦ v]`, розбір `"X=5, Y=2"` |
| `semantics/evaluate.py` | обчислення за AF_*, trace, `Undefined` (⊥), ліміт кроків |
| `semantics/poly.py`, `formula.py` | точні многочлени (`Fraction`), мова тверджень (`and or not ->`, `= != < <= > >=`) |
| `semantics/proof.py` | символьна індукція, інваріант/варіант, емпірична перевірка, контрприклади |
| `cli.py` | argparse, JSON-контракти, коди завершення |

## Принципи

* **Одне джерело істини.** Дерево, терм, обчислення й доведення читають один AST. Візуалізація будується з AST, а не з тексту програми.
* **Позиції скрізь.** Кожен вузол, крок правила й діагностика посилаються на `SourceSpan`.
* **Явні помилки.** Синтаксична помилка, ⊥ та перевищення ліміту — окремі коди й коди завершення; нічого не «ковтається».
* **Без залежностей.** Лише стандартна бібліотека (`argparse`, `fractions`, `json`, `xml` у тестах).
* **Детермінованість.** Однакові вхідні дані → однаковий вивід (порядок змінних — за першою появою).
