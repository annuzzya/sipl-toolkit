# SIPL Language Toolkit

Навчальний інструментарій для мови **SIPL** (простої імперативної мови з курсу «Теорія програмування»):
парсер, дерево синтаксичного виводу, автоматична побудова семантичних термів, обчислення термів на станах
та асистент доведення коректності програм. Чистий Python ≥ 3.10, **без зовнішніх залежностей**.

Проєкт індивідуальний; автор — Кучерова Анна, ТК-31, варіант 18 (приклад варіанта — `examples/sum_ap.sipl`,
але жодне значення варіанта у коді не «зашите»: інструмент працює з довільною програмою SIPL).

## Швидкий старт (демо на прикладі варіанта 18)

```bash
sipl check examples/sum_ap.sipl                                  # синтаксис, змінні, вхідні змінні
sipl tree  examples/sum_ap.sipl --format svg -o tree.svg         # дерево виводу (34 листки)
sipl tree  examples/sum_ap.sipl --format html -o tree.html       # те саме з підказками
sipl term  examples/sum_ap.sipl --explain                        # терм + застосовані правила NS_*
sipl eval  examples/sum_ap.sipl --state "N=3" --trace            # покрокове обчислення → [N↦0, S↦18, T↦9]
sipl prove examples/sum_ap.sipl --spec examples/sum_ap.proof.json   # доведення коректності
sipl prove examples/sum_ap.sipl --spec examples/bad_sum.proof.json  # спростування з контрприкладом
sipl eval  examples/loop_forever.sipl --max-steps 1000           # ⊥ — ліміт кроків
```

Будь-яку команду можна запускати на власній програмі, також зі stdin: `echo "begin x := 1 end" | sipl term -`.

## Команди

| Команда | Призначення | Корисні опції |
|---------|-------------|---------------|
| `check` | перевірка синтаксису, змінні, вхідні змінні | `--json` |
| `parse` | AST (текст або JSON з позиціями) | `--json`, `--seq-assoc left\|right` |
| `tree` | дерево виводу | `--format text\|json\|dot\|svg\|html`, `--labels bnf\|ua`, `-o файл` |
| `term` | семантичний терм | `--style unicode\|ascii\|latex`, `--explain`, `--json` |
| `eval` | значення терму на стані | `--state "X=5, Y=2"`, `--trace`, `--max-steps`, `--term файл.json`, `--json` |
| `prove` | асистент доведення | `--spec файл.json`, `--domain N`, `--json` |

## Коди завершення

| Код | Значення |
|----:|----------|
| 0 | успіх (для `prove` — доведено символьно) |
| 1 | синтаксична помилка програми |
| 2 | помилка використання або вхідних даних (немає файлу, некоректний стан, помилка специфікації) |
| 3 | значення терму ⊥ (змінна без значення, перевищено ліміт кроків) |
| 4 | твердження спростовано (знайдено контрприклад) |
| 5 | перевірено лише на обмеженій області (не є доведенням для всіх вхідних) |

JSON-режим (`--json`) видає стабільний контракт зі `schema_version: 1`, див. [docs/json-contracts.md](docs/json-contracts.md).

## Мова SIPL

```
Prog ::= begin Stm end
Stm  ::= x := Aexp | Stm ; Stm | if Bexp then Stm else Stm | while Bexp do Stm | begin Stm end | skip
Aexp ::= n | x | Aexp + Aexp | Aexp - Aexp | Aexp * Aexp | ( Aexp )
Bexp ::= Aexp = Aexp | Aexp > Aexp | Bexp ∨ Bexp | ¬ Bexp | ( Bexp )
```

Неоднозначності БНФ знімаються так: `*` пріоритетніше за `+ -`; `¬` пріоритетніше за `∨`; `;` ліво-асоціативна
(опція `--seq-assoc right`); тіла `if`/`while` — одиничні оператори (складений оператор береться в `begin … end`).
Замість `∨`/`¬` можна писати `or`/`not`. Коментар — `// …`. Повна EBNF — `grammar/sipl.ebnf`, пояснення — [docs/grammar.md](docs/grammar.md).

## Асистент доведення

Приймає програму виду «ініціалізація; while …; завершальні оператори» і JSON-специфікацію
(`pre`, `post`, `inputs`, `invariant`, `variant`, `closed_form`, `iterations`). Режими:

* **індукція за k** (`closed_form` + `iterations`): точна символьна перевірка (многочлени з раціональними
  коефіцієнтами) бази, кроку, поведінки умови циклу та післяумови — вердикт **proved**;
* **інваріант і варіант** (стиль Хоара): перевірки на обмеженій області — вердикт **bounded**;
* **емпірична перевірка**: реальний запуск семантичного терму, перевірка інваріанта й формули на кожній ітерації;
* будь-яка розбіжність → **refuted** з контрприкладом.

Асистент **не вигадує** інваріант: його задає користувач. Вкладені цикли та нелінійні умови виходять за межі
підтримуваного класу — це явно повідомляється. Докладно — [docs/proof-assistant.md](docs/proof-assistant.md).

## Обмеження

* Тільки цілі числа (в т.ч. від'ємні через `-`); ділення в SIPL немає.
* Асистент доведення працює з одним верхнім циклом без вкладених; не генерує інваріанти.
* «Обмежена область» — значення змінних 0…8 (змінюється `--domain`): це пошук контрприкладів, а не доведення.
* SVG великих програм широкий (масштабується в браузері).
